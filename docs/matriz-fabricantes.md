# Matriz de fabricantes de WAN Architect

## Flujo vigente del PR #11: selección y comparación

Fabricante/modelo se seleccionan **exclusivamente en Topología/editor de equipo**. Los cuatro módulos CLI recuperan modelos y puertos guardados; no piden otra selección ni confirmación física. Las doce fichas oficiales no cambian. El HTML contiene su copia generada y no depende de archivos data/ durante ejecución; JSON/JS se mantienen como fuente y paquete de datos verificable.

La comparación incorpora interfaces IPv4, VLAN/LAN, OSPF, DHCP/relay y administración para las cuatro marcas, usando extractos de adaptadores/equipos reales. Si falta un equipo/función compatible muestra el motivo, sin convertir roles ni fabricar comandos. Se conserva la equivalencia IOS/VRP adicional cuando es válida. La simulación usa listas de lectura propias por marca y no ejecuta CLI. AP sigue excluido de los cuatro generadores genéricos. Resultados y límite file://: [pruebas vigentes](pruebas.md); comportamiento: [manual](manual.md).

Las secciones siguientes conservan el historial del primer catálogo y adaptadores; esta sección gobierna la ubicación actual de selección/modelos y comparación. La validación de hardware sigue pendiente.

## Reglas compartidas para futuras implementaciones

1. Confirmar plataforma exacta, versión, funciones admitidas y nombres de interfaces antes de afirmar compatibilidad. Registrar fuente oficial y resultados de laboratorio; si faltan, mantener estado pendiente o bloqueado.
2. Mantener un plan coherente: VLAN por sede, gateway dentro de subred, ausencia de solapamientos, reserva de IP físicas/virtuales y enlaces enrutados completos. `assertReady` y `topologyIssues` bloquean incoherencias por inspección, pero cada rama de validación necesita pruebas.
3. Respetar dependencias actuales: OSPF requiere interfaces; DHCP requiere gateways/interfaces; switching con interfaces requiere VLAN. DHCP local y relay tienen validaciones de opciones. Probar combinaciones antes de cambiar controles.
4. Conservar salidas Cisco/Huawei y referencias v2 para migración y v3 para ida/vuelta antes de añadir adaptadores. El importador actual permite Cisco/Huawei, Fortinet (Firewall) y MikroTik (Router), en v4 con migración v2/v3; añadir nombres requiere una decisión de compatibilidad/migración y autorización de código, no solo nuevos botones.
5. Mantener sintaxis y capacidades separadas. Actualmente `generate` despacha Fortinet y MikroTik a adaptadores separados; el cuerpo IOS/VRP se conserva y los fabricantes desconocidos se rechazan. Pasar otro nombre no implementa una marca.
6. Mantener marcadores `<CAMBIAR_EN_PRODUCCION>`; no guardar contraseñas ni tokens reales. Los prompts de generación de claves y guardado se atienden fuera de la herramienta. Nunca ejecutar automáticamente las propuestas.
7. Probar bloqueos: equipo sin plan/enlaces, VLAN ausente, IP duplicada/fuera de red, grupo LACP incompleto y cores redundantes incompatibles. HSRP/VRRP no se interoperan entre sí; DHCP del core primario no proporciona replicación de concesiones.
8. No equiparar ACL administrativa a aislamiento entre servicios, ni enlace WAN a VPN/cifrado. Una política de firewall futura debe derivarse de requisitos explícitos, no inventarse desde un diagrama.
